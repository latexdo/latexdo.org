Research / AI harness

The code around the intelligence.

Context, tools, approval, and feedback: the machinery that lets an AI assistant work inside a LaTeX project.

01 / Context and capabilities

Start with the access you allow.

Settings control access to chat history, the current editor, project files, the bibliography, and researcher profile. Available tools also depend on the selected workspace tab and whether a document or selection is open.

02 / Model routing

One loop, several runtimes.

Local GGUF and Ollama requests use the desktop bridge. Cloud requests use the configured provider. Local GGUF inference runs through node-llama-cpp; cloud mode supports Anthropic and OpenAI-compatible endpoints. With a cloud provider, supplied context is sent to that provider.

03 / Actions and feedback

Tools return evidence to the conversation.

A tool call becomes a real read, edit, check, or compile action. Ask mode pauses proposed text edits for approval. Each tool result goes back to the model, which can continue or answer. Cancellation and the configured step budget bound the loop.

Based on the desktop source reviewed at revision 4059a3d . File paths are relative to the application repository.
